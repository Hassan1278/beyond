# Demo plan

This is a future rehearsal, not a completed demo or test result. First prove backend writing with real local Supabase Auth/Postgres and two users, including replay/revisions and AI-down saves, without frontend edits. Later use staging and fictional accounts/content; reset demo data deliberately, never production. Web and mobile call the independent API with bearer tokens; `services/ai` is separately owned/deployed and no provider is selected here.

1. Open the website and an installed Android or iOS preview build.
2. Sign in as the same fictional user on both.
3. Save a short entry on one interface and read it on the other.
4. Show the explicitly opted-in pending state only after next-morning resolver and lease/fencing/backoff/recovery tests. An explicitly enabled accelerated fictional staging rehearsal may exercise the durable pipeline, but cannot replace UTC/IANA morning/DST tests and must never force production delivery. A fake independent AI HTTP service is tests only, not production fallback.
5. Read/correct the reflection without overwriting the original letter; explicitly accept/reject an action and show a unique owned todo only after acceptance. Confirm later client behavior matches.
6. Explicitly approve a memory, then remove it and confirm it is absent.
7. Delete an entry with pending work and show no late reflection or replay resurrection; source-linked memories and reflection-derived todos follow the proposed privacy-first cascade, while standalone todos remain.
8. Show a second fictional user cannot access the first user's content.
