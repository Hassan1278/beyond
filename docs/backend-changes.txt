Why:
The user authorized architecture documentation before implementation. The prior all-in-one web API design conflicts with independent backend ownership/deployment and writing availability during AI outages. The new target keeps one monorepo and portable shared contracts but separates API, AI and frontend deploy/test/environment boundaries. API owns auth/RLS/database/queue/jobs/finalize/deletion; AI owns prompts/providers and optional RAG/transcription without DB admin keys. Both first-party clients use freshly verified Supabase bearer tokens and active profiles; Supabase retains password/sign-in/reset/refresh ownership. Exact browser CORS is not auth, and private responses are not cached.

Design recorded:
- Public cheap liveness and bounded config/DB-schema readiness are independent of AI and expose no secrets. Protected dependency/queue status is later.
- Writing acceptance uses real local Supabase Auth/Postgres and two users for save/read/edit/delete, creation equality/replay and revisions; AI downtime cannot prevent saves.
- Atomic entry plus eligible job is opt-in only. Tested next-local-calendar-morning UTC/IANA resolution and leases/fencing/backoff/recovery precede processing. Tones: friend, mentor, future, diary. Morning times: 07:00, 07:30, 08:00. Preference changes affect future jobs; edits invalidate old revisions.
- Independent versioned AI HTTP generation returns letter/actions/provenance from entry/revision/tone/bounded authorized context. Fake independent AI HTTP service is tests only, never a production fallback. No provider is selected. No automatic todos/memories; decisions and corrections are explicit/separate.
- Proposed profiles, journal_entries, reflection_jobs, reflections, approved_memories and todos schema includes RLS, grants and validated RPCs. Unique owner/key plus immutable original creation equality prevents duplicates; equivalent replay returns current persisted state without reverting edits or duplicating jobs. Deletion clears original payload, content and consent before retaining minimum IDs/owner/key/deleted_at only. APIs/RLS/RPC resource visibility excludes tombstones; ordinary deleted reads return 404 and own retired-key creation returns 409 before payload comparison.
- Proposed privacy-first source deletion removes reflections, source-linked approved memories and derived todos; standalone todos remain. Account deleting gate and durable retry precede Auth deletion. Runtime deletion tests do not exist yet.
- Voice is a later second core input: private Storage, metadata/transcription job kind, separate consent and reviewed transcript into text flow. Optional RAG requires user-scoped source/provenance/deletion contracts. Full patterns/Life Film are later; no fake counts or AI end-to-end-encryption/perfect-safety guarantees.
