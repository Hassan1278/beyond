# Setup

Use Node24.20.0 and npm11.19.0. Install workspaces from the root with `npm ci`; keep one root lockfile. See [architecture](architecture.md) for how the pieces fit.

Copy `backend/api/.env.example`, `frontend/web/.env.example` and `frontend/mobile/.env.example` to their workspace's `.env.local`. Fill in public Supabase URL/key and the API URL on clients. Only the API receives optional privileged worker credentials. Never commit local environment files.

For local Supabase with Docker:

```sh
npm run db:start
npx supabase status
npm run db:test
```

The configured project is `beyond`; ports are API55321, DB55322, Mailpit55324. The start script excludes unnecessary realtime/storage/studio services for the text MVP. Docker binds locally for development; do not expose this stack as production. Apply additive migrations to a hosted project only as a separate authorized deployment step.

Run API and web separately:

```sh
npm run dev:api -- --port 3002
npm run dev:web
```

The browser is at `http://localhost:3000/#/app`. Include that exact origin in API CORS. Marketing pages use `#/`, `#/privacy`, `#/beta`; the fictional pitch is `?demo=1#/app`, with optional `mode=present` or `mode=app`. An unconfigured product app shows setup information and no fictional user data.

In Supabase Auth, configure a site URL and allow the web `/auth/callback` redirect and `/auth/callback?flow=recovery` recovery variant. Enable email/password and email delivery/confirmation appropriate to the environment. Enable Google with its provider credentials and Supabase provider callback; client redirects still use the configured web/native allowlist. PKCE confirmation/recovery uses the initiating browser/device's verifier, so opening a link elsewhere may require starting the flow again.

```sh
npm run dev:mobile
```

The native API must be reachable from the device over HTTPS; a phone's127.0.0.1 is the phone itself. Use a development build for native modules. Allow the exact redirect generated by `Linking.createURL('/auth/callback',{scheme:'beyond'})` for the installed app. Expo Go/development URLs differ and must be configured explicitly when used. Keep bundle/package identifiers provisional until confirmed before EAS registration/store builds.

Checks:

```sh
npm run check:deps
npm run format:check
npm run lint
npm run typecheck
npm test
npm run test:design
npm run test:palette
npm run build:api
npm run build:web
npm run check:mobile
```

Real local acceptance starts from a running verified local stack and an API production build:

```sh
npm run test:api:writing
```

For the connected browser test, install Playwright Chromium, run `node tests/build-connected-web.mjs` while local Supabase is running, then set `TEST_CONNECTED_BROWSER=true` when running the acceptance script. The runner guards loopback/project/ports before fixture admin actions and cleans only captured fictional users. CI performs this sequence. Never aim these harnesses at a hosted project.
